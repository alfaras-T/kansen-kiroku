# Ball Films

> その日の1点を、一枚のフィルムに。

野球観戦で撮った写真に、日付・スコア・球場を重ねて保存・共有するアプリです。
Expo（React Native / TypeScript）製で、iOS・Android・Webを同一コードから作っています。

記録はサーバーに送信せず、**端末内にのみ保存**します。アカウント登録もログインも不要です。

リポジトリ名とURLスラッグに残る `kansen-kiroku` は旧名です。互換性のため内部識別子としてのみ残しています。

---

## 設計方針

この3つが、実装上の多くの判断の理由になっています。

**球団のロゴ・正式名称（企業名）を使わない。** 表示するのは愛称と略称（例: ジャイアンツ / G）だけです。
一方で、球団カラーは公式に公表されている色をそのまま使っています（`TEAM_BRAND_COLORS`）。

**サーバーを持たない。** 観戦履歴もサムネイルも端末内で完結します。この方針の裏返しとして、
アプリを削除すると記録は戻りません。バックアップの書き出し・読み込みと、記録が貯まったときの
案内でこれを補っています。

**写真加工アプリであって、記録アプリではない。** 観戦記録と成績集計も持っていますが、
このアプリの中心は「生成される一枚の美しさ」です。機能を足すかどうかは、この基準で判断しています。

## 主な機能

### 一枚を作る（記録する タブ）

写真を選ぶと、その場でテロップ付きのプレビューが表示され、入力するそばから仕上がりが変わります。

- **出力サイズ** … 元のサイズ / スクエア(1:1) / ポートレート(4:5) / ストーリー(9:16)
- **表示位置** … 右下・左下・右上・左上
- **スタイル** … 3プリセット（後述）
- 文字サイズ、写真の拡大・位置調整、勝敗ハイライト、自由メモ
- 保存と共有は別ボタン（共有だけでは写真アプリに追加されません）

### スタイルプリセット

3つとも異なる手法で性格を作っています。色違いではありません。

| | 構造 | 手法 |
|---|---|---|
| **クラシック** | 積み上げ・スコアが主役 | 基準となる階層 |
| **フィルム** | 一列・すべて同色同サイズ | 日付を発光させ、`'26 8 3` 表記にする |
| **ミニマル** | 積み上げ・スコアが主役 | 色を引く（球団カラーも使わない） |

フィルムだけ構造が違います。実際のフィルムカメラの焼き込みは要素ごとの大小や色の差を持たないため、
一列に並べています。勝敗ハイライトも効かせません。

### 球団カラー

設定したマイチームが**出場している試合のみ**、日付と区切り線がその球団の色になります。
他球団同士の試合ではプリセットの既定色に戻ります。色が「自分のチームの試合だった」という
情報を持つようにするためです。

濃紺や黒のメインカラーは写真の上で沈むため、**色相と彩度を保ったまま明度だけを上げた**色を使います
（`resolveTelopTeamColor`）。別の色に振り替えるのではなく同じ色の明るい版なので、球団の色として
認識できます。マリーンズの黒だけは色相を持たないため、無彩色の例外として白寄りに引き上げます。

### 観戦履歴（観戦履歴 タブ）

- 記録の一覧・編集・削除、マイチーム設定による通算成績の自動集計
- **観戦まとめ** … その年の成績・球場・連勝などを一枚にまとめる
- **フィルムシート** … その年の観戦を格子に並べる。各コマに ○（勝）●（負）△（分）が付く
- 記録が貯まるとバックアップを案内（20件以上、かつ前回案内から20件増えたとき）

## 技術構成

- Expo SDK 57 / React Native 0.86 / React 19（TypeScript）
- ルーティング: `expo-router`
- 画像書き出し: `react-native-view-shot`（ネイティブ）/ `html-to-image`（Web）
- 保存・共有: `expo-media-library`, `expo-sharing`
- 永続化: `@react-native-async-storage/async-storage`、サムネイルは `expo-file-system`
- フォント: Bebas Neue, Montserrat, Oswald, JetBrains Mono（`@expo-google-fonts/*`）

### ディレクトリ

```
src/
├── app/          画面（expo-router）
├── components/   UI部品・カード（overlay-card, wrapup-card, proof-sheet-card）
├── constants/    テーマ・球団・球場・テロップのプリセット
├── contexts/     create-form（入力状態）, favorite-team（配色とマイチーム）
├── storage/      history, backup, thumbnails, preferences
└── utils/        画像処理、年間集計、ダイアログ
```

```bash
npm install
npx expo start        # Expo Go で確認
npx expo start --web  # ブラウザで確認
```

## 実装上の注意点

同じ問題で時間を溶かさないための記録です。いずれも実際に踏んだものです。

### expo-media-library はルートから読み込まない

SDK 57 でルートの `expo-media-library` はクラスベースの新APIに置き換わりました。
`saveToLibraryAsync` などの旧関数は名前だけ残っていますが、**実行時に必ず例外を投げるスタブ**です。
型チェックもビルドも通るのに保存時だけ失敗します。

```ts
// NG
const MediaLibrary = await import('expo-media-library');
// OK
const MediaLibrary = await import('expo-media-library/legacy');
```

### captureRef は file:// の付かないパスを返す

iOSの `captureRef` は `RCTTempFilePath()` の戻り値をそのまま返すため、スキームがありません。
`expo-media-library` の iOS 実装は `Data(contentsOf:)` でファイルを読むので、スキームがないと読めません。
保存・共有の前に `file://` を補う必要があります。

### テロップの拡大に transform: scale を使わない

`transform` は描画済みの結果を引き伸ばす処理です。書き出し用カードはプレビューの8〜9倍あるため、
小さく描かれた文字が拡大されて輪郭が潰れます。フォントサイズ・行間・字間・余白の**実寸を掛け算**して、
その大きさで文字が描き直されるようにしています。

同じ理由で、`captureRef` の `width`/`height` 指定による拡大も避けています。レイアウトのやり直しでは
なく拡大だからです。書き出しは、目的の解像度でレイアウト済みの隠しステージを直接キャプチャします。

### 隠しステージのキャプチャ

書き出し用のカードは `opacity: 0` のラッパー内に置いています。キャプチャ対象はラッパーではなく
**中のカード自身**なので、透明度は結果に影響しません。

背景写真がある場合は、**キャプチャ対象のカード自身の `onLoad`** を待つ必要があります。
プレビュー側の `onLoad` だけを見ていると、書き出し用カードの写真が未読み込みのまま撮ってしまいます。

### バージョンの手動固定をしない

Expo関連のパッケージを `^` なしで手で固定すると、壊れた組み合わせが凍結されて自動解決が効かなくなります。
`npx expo-doctor` で検出し、`npx expo install --fix` で直すのが正しい経路です。

### Alert.alert は react-native-web で動かない

`src/utils/dialogs.ts` の `notify()` / `confirmAsync()` を使ってください。

### iOS の共有シートが英語になる

アプリが日本語のローカライズを持たないと、iOSはアプリを英語アプリとみなし、共有シートなど
OS提供のUIを英語で表示します。`app.json` の `CFBundleDevelopmentRegion` / `CFBundleLocalizations` と
`locales/ja.json` で日本語を宣言しています。
